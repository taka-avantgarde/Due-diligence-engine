## ⚡ البدء السريع

**التثبيت مرة واحدة:**

```bash
python3 -m pip install --no-cache-dir git+https://github.com/Atlas-Associates-Inc/Due-diligence-engine.git
```

**التشغيل من مجلد مشروعك:**

```bash
dde prompt --pdf
```

استخدم أي طرفية لبيئة تطوير مدعومة بالذكاء الاصطناعي (Claude Code / Cursor / Copilot). يقرأ الذكاء الاصطناعي قاعدة الكود، ويقيّمها كمستشار تقني من الطراز العالمي، ويكتب ملف PDF من 24 صفحة إلى `~/Downloads/`. **بلا مفاتيح API. بلا سحابة. بلا تكلفة إضافية.**

## 💭 كيف تحصل على أفضل النتائج

> **باختصار**: شغّل أعلى مستوى من الذكاء الاصطناعي تملك صلاحية الوصول إليه في طرفية بيئة التطوير لديك،
> الصق الأمر، وانتظر من 10 إلى 20 دقيقة. هذا كل شيء.

**الإعداد الموصى به:**

- **شغّل أقوى نموذج متاح** في بيئة التطوير لديك (Claude Fable 5 أو GPT-5 أو Gemini 2.5 Pro، وما إلى ذلك)
- **الصق `dde prompt --pdf`** في الطرفية
- **اذهب لاحتساء قهوة** ☕ — سيقرأ الذكاء الاصطناعي مئات الملفات، ويقيّم عبر
  أكثر من 9 أبعاد، ويبحث عن 5 إلى 10 منافسين عالميًا، ويبني ملف PDF استشاري من 24 صفحة
- **الوقت المتوقع**: **10 إلى 20 دقيقة** (أطول لقواعد الكود الكبيرة أو النماذج الأعمق)

**لماذا هذا النهج؟**

| الاعتبار | الإجابة |
|---------|--------|
| 🔐 **تسرّب البيانات؟** | لا شيء. كل شيء يعمل داخل بيئة العزل الخاصة بالذكاء الاصطناعي في بيئة التطوير لديك — لا خوادم طرف ثالث، ولا قياس عن بُعد. وDDE نفسه هو Python محلي 100% |
| 💰 **التكلفة؟** | $0 إضافية. يستخدم اشتراك الذكاء الاصطناعي الموجود لديك بالفعل في بيئة التطوير |
| 🔑 **مفاتيح API؟** | غير مطلوبة. بيئة التطوير لديك تتولى بالفعل مصادقة الذكاء الاصطناعي |
| ⚙️ **الإعداد؟** | فقط `python3 -m pip install`. بلا تهيئة، بلا حسابات |
| 🎁 **المقابل الخفي؟** | لا يوجد. DDE هو **مشروع هواية** — بُني وفُتح مصدره للمتعة. استخدمه بحرية |

> **صُنع على يد مطوّر منفرد كهواية.** إن كان مفيدًا لك، فهذه مكافأة كافية. ضع نجمة على المستودع إن أعجبك ⭐

## 💻 أين يعمل DDE — استخدم الذكاء الاصطناعي الذي تملكه بالفعل

يولّد DDE موجِّهًا (prompt) منظَّمًا. **أي وكيل ذكاء اصطناعي قادر على قراءة الملفات وتنفيذ أوامر الصدفة (shell)** يمكنه تشغيله. لا حاجة إلى تكامل أو إضافة أو تسجيل دخول خاص بـ DDE.

**تم التحقق من عمله** (وثائق رسمية + اختبار، 2026-05):
- ✅ [**Claude Code**](https://code.claude.com/docs/en/overview) (CLI / VS Code / JetBrains / Desktop / Web — رسمي من Anthropic)
- ✅ [**GitHub Copilot Agent Mode**](https://docs.github.com/en/copilot/using-github-copilot/copilot-chat/asking-github-copilot-questions-in-your-ide) (VS Code / Visual Studio / JetBrains / Xcode / Eclipse — متاح بشكل عام)

**من المفترض أن يعمل** (المتطلبات: قراءة الملفات + تنفيذ الصدفة + ويُفضَّل البحث على الويب):
- Cursor Agent وGemini Code Assist وContinue.dev وCody (Sourcegraph) وAider وWindsurf وAmazon Q Developer وJetBrains AI Assistant، والطرفيات الوكيلة المماثلة.

> ✅ إن كنت تستخدم بالفعل أيًّا مما سبق، فأنت على بُعد أمر `pip install` واحد من تشغيل DDE اليوم.
> هل أكّدت عمل طرفية معينة؟ أخبرنا في [مشكلة (issue)](https://github.com/Atlas-Associates-Inc/Due-diligence-engine/issues).

### 💰 بلا تكلفة إضافية

**تدفع فقط مقابل اشتراك الذكاء الاصطناعي الذي تملكه بالفعل.** Claude Code Pro / GitHub Copilot / Cursor Pro / Gemini Advanced — يعمل DDE ضمن حصة الذكاء الاصطناعي الموجودة لديك. لا مستويات تسعير لـ DDE، ولا مفاتيح API إضافية، ولا رسوم خفية، على الإطلاق.

## ما الذي يميّز DDE

معظم "مراجعي الكود بالذكاء الاصطناعي" يتحققون من:
> *"هل يحتوي على مصادقة؟ ✓ هل يحتوي على HTTPS؟ ✓ هل يحتوي على اختبارات؟ ✓"*

هذا امتثال بقائمة تحقّق. **أما DDE فيتعمّق أكثر:**

> *"هل التشفير بـ Signal Protocol؟ هل هو PQXDH مع ML-KEM-1024؟
> هل بُني على libsignal/BoringSSL FFI، أم على تشفير مصنوع ذاتيًا؟
> هل ينشر الفريق أبحاثًا في التشفير؟"*

مبني على **فلسفة Atlas الهندسية**: هندسة أمن سيبراني جادّة
عبر التشفير والخصوصية والاتصالات والدفاع المتعدد الطبقات — مقروءة مباشرةً
من الكود المصدري. الامتثال بقائمة التحقّق (شهادات SOC2 وMFA وWebAuthn)
هو للمرجعية فقط، ولا يُحتسب أبدًا في النقاط.

**🌐 جديد في v0.3.2**: قبل قراءة أي كود، يُجري الذكاء الاصطناعي **عمليات بحث ويب مباشرة** عن أحدث مشهد للمنافسين (الاستحواذات والإغلاقات والداخلين الجدد)، وجولات تمويل 2026، وثغرات CVE الأخيرة، والتحوّلات التنظيمية. كل منافس وكل خلية في مصفوفة التنفيذ تحمل **رابط مصدر + تاريخ تحقّق**، ويبدأ مُخرَج JSON بكتلة `data_freshness` تتعقّب كل استعلام بحث. **التحليل القديم المعتمد على حدّ تدريب فقط مُستبعَد هيكليًا.** **(v0.5.0)** أصبح هذا المصدر يظهر الآن مباشرةً داخل PDF — يعرض صندوق مصدر البيانات في لوحة النقاط تاريخ البحث وعدد الاستعلامات/المصادر، أو تحذيرًا واضحًا بالاعتماد على بيانات التدريب فقط عند عدم تنفيذ البحث على الويب.

## 🆕 مصفوفة قدرات التنفيذ

المخطط التنافسي الثامن — **~30 عنصرًا × 5-10 من كبار المنافسين العالميين**:

```
                        Target   Comp. A   Comp. B   Comp. C   Comp. D   ...
Encryption (core differentiator)
  Feature 1              ○        ○         ×         △         ○
  Feature 2              ○        ○         ×         ×         ○
  Feature 3              ○        ○         ○         ×         ○
  Feature 4              ○        ×         ×         △         △
  ...
Privacy & Compliance
  Feature 1              ○        △         ○         ×         △
  Feature 2              ○        ○         △         ×         ×
  ...
```

العناصر والمنافسون يُختارون **ديناميكيًا حسب صناعة الهدف**
(المراسلة، التقنية المالية، الطب، الألعاب، SaaS، إنترنت الأشياء، وما إلى ذلك).

ترميز بأربع حالات (معيار التقييم التقني الياباني):
- **○ مُتحقَّق منه** (تنفيذ موثّق علنًا)
- **△ مُدّعى** (مزعوم، غير قابل للتحقق)
- **× غير منفَّذ** (غائب صراحةً)
- **? غير معروف** (لا يمكن تحديده — يُفضَّل على التخمين)

بالإضافة إلى **منطق اختيار المنافسين** — من 3 إلى 5 أسطر لكل منافس تشرح لماذا اختير ذلك
المنافس المحدد كهدف للمقارنة (المقر الرئيسي، الموقع السوقي، الفئة).

## 🛠️ الاستخدام

> 🌍 **لغات التقرير (14):** `en` `ja` `es` `fr` `de` `pt` `nl` `it` `id` `zh` `ko` `vi` `th` `ar` — مثال: `dde prompt --pdf --lang ar`. تُعرض العربية بتشكيل سياقي واتجاه RTL (يظل تخطيط الصفحة LTR).

```bash
# Current directory, English PDF
dde prompt --pdf

# Japanese PDF
dde prompt --pdf --lang ja

# GitHub repo with stage context
dde prompt owner/repo --pdf --lang ja --stage seed

# Non-interactive (for AI terminals without prompt support)
dde prompt --pdf --lang ja \
  --url https://example.com \
  --url https://docs.example.com

# Direct BYOK multi-AI cross-verification (optional)
export ANTHROPIC_API_KEY=sk-ant-...
export GOOGLE_AI_API_KEY=AIza...
export OPENAI_API_KEY=sk-...
dde analyze owner/repo
```

## ❓ الأسئلة الشائعة

**س: هل يرسل DDE الكود الخاص بي إلى أي مكان؟**
ج: لا. `dde prompt` يعمل محليًا بالكامل — يولّد موجِّهًا منظَّمًا يقرأه الذكاء الاصطناعي في بيئة التطوير لديك. يقيّم الذكاء الاصطناعي الكود في موضعه. أما `dde analyze` الاختياري (BYOK) فيرسل إلى مزوّدي الذكاء الاصطناعي باستخدام نقاط نهايتهم بلا احتفاظ فقط.

**س: لماذا هو مجاني؟ ما المقابل الخفي؟**
ج: لا يوجد مقابل خفي. DDE مفتوح المصدر (Apache 2.0) ويستخدم اشتراك الذكاء الاصطناعي الموجود لديك بالفعل في بيئة التطوير (Claude Code / Cursor / Copilot). لا قياس عن بُعد، ولا بيع إضافي.

**س: هل يمكنني استخدامه في التكامل المستمر (CI)؟**
ج: نعم — راجع [`action.yml`](action.yml). أضف GitHub Action إلى طلبات السحب للحصول على تقييم عناية واجبة آلي.

**س: ما مدى دقة المخططات التنافسية؟**
ج: المخططات يبحث عنها الذكاء الاصطناعي من مصادر عامة (الأوراق البيضاء، GitHub، المدونات، تقارير SOC2). تعتمد درجة الثقة على شفافية المنافس. استخدم `?` (غير معروف) بسخاء — الإيجابيات الكاذبة تضرّ بالمصداقية أكثر من الفجوات.

**س: أليست بيانات المنافسين قديمة؟ حدود تدريب الذكاء الاصطناعي عمرها من 6 إلى 12 شهرًا.**
ج: اعتبارًا من v0.3.2، أصبحت **الخطوة 0 "البحث المباشر على الويب" إلزامية**. قبل قراءة أي كود، يُجري الذكاء الاصطناعي WebSearch / WebFetch لتحرّكات المنافسين في 2025-2026 (الاستحواذات والإغلاقات والداخلين الجدد)، وأحدث جولات التمويل، وثغرات CVE، والتحوّلات التنظيمية. كل منافس وخلية مصفوفة تحمل حقل `sources` (رابط) و`last_verified` (تاريخ)، ويبدأ مُخرَج JSON بكتلة `data_freshness` تتعقّب كل استعلام بحث نُفِّذ. وعندما تفتقر بيئة التشغيل إلى أدوات البحث على الويب، يجب على الذكاء الاصطناعي أن يكتب `data_cutoff_warning` — **لا مُخرَج قديم صامت بحكم التصميم**.

**س: لماذا "فلسفة Atlas الهندسية"؟**
ج: DDE مبني على يد **Atlas Associates Inc**، الشركة التي تقف وراء Arc Messenger (مراسلة مشفّرة من طرف إلى طرف بـ libsignal + PQXDH). يعكس التقييم رباعي المحاور ما نبحث عنه فعليًا عند تقييم التقنية.

**س: هل يمكنني تخصيص أوزان النقاط؟**
ج: أوزان الأبعاد الخمسة متساوية بنسبة 20% لكل منها (متوازنة، بسيطة، قابلة للتفسير). أوزان Atlas رباعية المحاور (20/20/5/55) تعكس فلسفة Atlas وهي ثابتة أيضًا. أوزان العناصر الفرعية ضمن قوة الأمن تتكيّف حسب سياق الصناعة.

**س: ماذا لو لم يكن مشروعي حرجًا أمنيًا؟**
ج: نقاط الأبعاد الخمسة (جودة المعمارية تشمل الموقف الأمني بنسبة متوازنة 20%) هي نقاطك الأساسية. ولوحة Atlas رباعية المحاور هي عرض مرجعي موازٍ — يُعرض كلاهما.

**س: تظهر لي `command not found: pip` — كيف أُثبّت؟**
ج: استخدم `python3 -m pip install ...` بدلًا منه. لم يعد macOS Homebrew Python 3.12+ يأتي بأمر `pip` مجرد. صيغة `python3 -m pip` تعمل على جميع المنصات (macOS / Linux / Windows / venv / pyenv / conda).

**س: لماذا لا تؤثر شهادات الطرف الثالث (SOC2 وISO وHIPAA) على النقاط؟**
ج: يقيّم DDE الكود المصدري، لا الشارة. خدمة معتمَدة بـ SOC2 تخزّن نصًا صريحًا لا تزال تملك تخزينًا بنص صريح. وخدمة غير معتمَدة بـ libsignal+PQXDH لا تزال قوية تشفيريًا. تُعرض الشهادات للسياق لكنها لا تُحتسب أبدًا في النقاط — راجع صفحة التفصيل الفرعي للأمن.
